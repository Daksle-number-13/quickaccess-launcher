# QuickAccess v2.0.2 기능·안정성·성능 검증

검증일: 2026-09-07. 범위는 초기 제품 명세와 이후 추가된 웹 링크, 검색,
설정 백업, 업데이트 확인, 다중 모니터 사전 준비, 배포 도구입니다.

## 확인한 문제와 수정

- 팝업 투명 배경 적용 후 Windows 도구 창 속성이 사라져 작업표시줄에
  `CTkToplevel`이 나타나는 문제를 수정했습니다.
- 느린 경로가 작업자를 모두 점유해 정상 경로까지 처리가 중단되는 문제를
  유한한 대체 작업자와 대기 제한으로 보완했습니다.
- 검정색·투명 아이콘 처리와 EXE/LNK 아이콘 조회 고착을 보완했습니다.
  조회가 늦어지면 기본 아이콘을 쓰며 패널 호출은 기다리지 않습니다.
- 설정 읽기 크기·중첩 오류를 제한하고 정상 rolling backup을 보존합니다.
  기본 파일이 없어졌을 때도 유효한 백업을 먼저 복원합니다.
- 자동 실행 명령의 Windows 길이 제한을 사전 확인합니다. 이전 EXE 경로의
  복구와 저장 실패 시 되돌리기는 계속 지원합니다.
- 다른 배율 모니터에서 설정·알림·입력창의 최초 위치와 크기를 표시 전에
  준비하고, 앱 정보에 확인 대화상자가 있는 종료 버튼을 추가했습니다.
- 트레이·핫키 서비스의 실제 상태를 확인하고 제한된 재시도로 복구합니다.
- 탐색기 빠른 등록의 COM 호출이 멈춘 뒤 반복 재시도하면 작업자가 누적되던
  문제를 재현해 수정했습니다. 실제로 실행 중인 작업은 최대 2개입니다.
- 5,000자리 업데이트 버전 응답을 안전하게 거부합니다. 업데이트 작업 예외와
  스레드 시작 실패가 이후 확인을 영구 차단하지 않도록 수정했습니다.
- 무인 실행 검사의 숨은 오류창, 조기 종료, Tk 콜백 오류, 다른 검사 인스턴스로
  인한 잘못된 성공 판정을 막았습니다. 빌드는 실제 종료 코드와 시간 제한을
  확인하고 실패한 EXE·임시 폴더·자식 프로세스를 정리합니다.

## 성능

100%·200%·100% 배율의 Windows 3모니터 PC에서 측정했습니다. 수치는 OS 첫 픽셀
합성 시간이 아닌 앱 표시 호출 또는 창 노출 신호 기준입니다.

| 조건 | 표시 호출 p95 | 명령부터 노출 p95 | 결과 |
| --- | ---: | ---: | --- |
| 20개 항목 반복 호출, 30회 | 4.4ms | 16.9ms | 재렌더 0회 |
| 20개 항목 혼합 DPI 전환 | 4.4ms | 12.7ms | 36/36회 성공, 지연 재표시 0회 |
| 200개 항목 반복 호출, 30회 | 16.6ms | 12.1ms | 25ms 표시 기준 통과, 재렌더 0회 |

200개 항목의 최초 화면 준비는 약 4.73초입니다. 이 준비는 앱 시작 시 수행하며
상주 중 단축키는 준비된 화면을 재사용합니다. 8월 31일 후보 EXE의 6회 실행은
모두 정상 종료했고, 첫 상주 준비 약 2.93초·후속 중앙값 약 2.89초였습니다.
조건과 상세 수치는 [PERFORMANCE.md](PERFORMANCE.md)에 있습니다.

## 실환경에서 추가 확인할 항목

현재 장비에서 기존 9개 항목과 자동 실행 선호가 유지되며, Windows Run 등록이
현재 `dist/QuickAccess.exe --startup`과 일치함을 읽기 전용으로 확인했습니다.
실제 재부팅 후 자동 실행은 이번 검사에서 수행하지 않았습니다.

아래 항목은 자동 검사 통과로 대체할 수 없으므로 별도 현장 검증이 필요합니다.

- Python이 설치되지 않은 깨끗한 Windows 10/11 PC, 회사 EDR/백신 정책
- 재부팅·로그인 직후 자동 실행과 첫 화면
- 실제 Windows 11 탐색기 탭·OneDrive·연결이 끊긴 UNC의 다양한 조합
- 125%·150% 배율과 작업표시줄 위치를 바꾼 물리 모니터 구성
- 실제 업무 앱·한글 IME와 사용자 지정 핫키 충돌 여부

모사된 실패 경로와 실제 장비 측정을 구분해 기록했으며, 모든 Windows 환경에서
오류가 없다는 보증으로 해석하지 않습니다. 코드 서명 인증서는 별도 준비 대상이며
이번 배포 상태는 `NotSigned`입니다.
